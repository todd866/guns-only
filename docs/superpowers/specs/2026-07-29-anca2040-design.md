## Doctrine (binding constraints)

1. **AI-first redesign.** ANCA2040 trains for a battlespace where machines hold most of the
   shared mental model and speak most of the R/T. The panel and the radio are that redesign
   made playable: automation acts and narrates; the human judges. See
   `audio/radio/mission/README.md`.
2. **The automation does it; the panel shows it.** ANCA is an SA panel on what the jet
   is doing for the player automatically. No player chores, ever. Radio speaks sparse
   deltas; the drawer exposes currently relevant automation truth when requested — never
   a task list or a second copy of every instrument.
3. **Presentation must not outrun the kernel.** Every rendered fact binds to sim truth
   already in (or added to) the snapshot. No client-side guessing.
4. **The HUD stays instrument-true.** The panel is a DOM element outside the HUD canvas,
   not a HUD symbol.
5. **Optional means stowed.** Every tier gets one quiet ANCA control, closed by default.
   Opening it is a deliberate cross-check, not a prerequisite for flying the sortie.
6. **One condition, one primary owner.** ANCA does not repeat the HUD, systems panel,
   limits panel, radio caption, or action-console alarm on its stowed control. Exceptions
   remain legible inside the deliberately opened drawer. A future ANCA-exclusive
   condition may notify only by opting into that behavior explicitly.

## Disclosure policy (binding)

A proposed ANCA fact must pass all five gates:

1. **Truth:** the fact binds directly to current snapshot/kernel state.
2. **Automation:** it describes what automation is doing, waiting on, or protecting;
   player-performed work is not ANCA.
3. **Relevance:** it is a live transition, a phase-relevant deliberate cross-check, or an
   exception with a decision consequence.
4. **Ownership:** no more specific visible surface already owns the same routine fact.
   Exception detail may be available in the open drawer, but must not create a second
   unsolicited alarm.
5. **Expiry:** the rule states exactly when the fact disappears. Completed checklists,
   clean cruise configuration, idle tuning, and pre-threshold fuel arithmetic do not
   linger.

Tone is semantic, not decorative:

- `active` (blue): automation is changing or transmitting now.
- `steady`: a phase-relevant state the player deliberately asked to cross-check.
- `attention` (amber): an exception visible inside the open drawer.
- `notify`: separate from tone and false by default; only an ANCA-exclusive condition may
  light the stowed control.

## The ANCA panel — UX

Present at every tier, stowable and view-only.

**Stowed (default on portrait and laptop):** one compact `ANCA` control on the right rail,
positioned clear of action consoles and touch reservations. It stays quiet for routine
automation and for warnings already owned by another surface.

**Open (on request):** a compact four-row drawer, top-right and outside the HUD zone. The
same interaction and information hierarchy holds on portrait and laptop; portrait keeps
the drawer above the touch controls. Only rows that pass the disclosure policy render; if
none do, the drawer says `ROUTINE STATE · NOTHING TO CROSS-CHECK`. Tapping the ANCA
control again stows it immediately.

| Row | Shows when | Example | Primary routine owner |
|-----|------------|---------|-----------------------|
| **A** Aviate | Automatic configuration is moving; recovery configuration is being deliberately cross-checked in approach context; or configuration is unsafe/overspeed/split | `AUTO RECOVERY CONFIG · GEAR DN · FLAPS LDG` | HUD + systems panel |
| **N** Navigate | RTB automation is active; joker/bingo has crossed; or projected reserve is negative | `RTB CVA-31 · ETA 12 MIN · ARR 2970 LB · +1970 LB RES` | limits/navigation panel |
| **C** Communicate | Automation is actively transmitting; transcript never appears here | `TOWER · AUTO TX` | audio + optional radio caption |
| **A** Administrate | An automatic checklist is incomplete; completed checklists disappear. Reserve consequence stays in Navigate | `LAUNCH · AUTO 2/4 → GEAR UP` | mission director |

## Checklist engine (the one new sim subsystem)

`sim/MissionChecklists.cs` — checklist definitions as **data** per beat phase. V1
checklists, constrained to items with real sim truth behind them (implementation research
2026-07-29): **LAUNCH** (cat stroke, airborne, gear up, flaps up), **COMMIT** (the
fence-in substitute — Intercept-phase commit + weapons authorized; the sim has no
master-arm/fence switch), **RECOVERY** (gear down and locked, flaps landing — no hook
state exists [the hook is fixed geometry] and no harness state exists, so those items are
cut rather than faked). Design:

- Every item is a **predicate over sim truth** evaluated at tick boundaries. Items
  complete themselves because the automation genuinely did the thing. Nothing is ever
  handed to the player.
- Completion events are exposed to `MissionRadio` so admin milestones can be narrated
  in-register ("fence in" call) — the C and A channels tie together.
- State resets on beat start; each predicate fires exactly once per checklist activation.

**Snapshot additions:** a small `checklist_*` block — id/name, done count, total,
next-pending item label. Full contract ritual: `SnapshotHotFrame` LayoutVersion 16 → 17,
schema 1.21.0 → 1.22.0 in `SnapshotProjection.cs` **and both** `pack.json` copies, plus
every test pin (including the escaped-regex pins in
`g_tolerance_bridge_contract.test.mjs`).

## Modules and data flow

New `web/wwwroot/render/anca/`:

- `anca_view_model.js` — pure function: snapshot → four row structs
  (`{letter, key, line, tone, shown, notify}`) plus the filtered `shownRows`. A/N/C
  compose here from existing fields; the fourth row binds `checklist_*`. Row definitions
  are data so the medical sim can later re-skin the first channel as Attention without
  touching the renderer.
- `anca_panel.js` — DOM renderer (stowed control + optional drawer), wired in `app.js`; styles
  follow existing panel CSS conventions.

## Error handling

- Missing, routine, complete, or irrelevant fields → the row is omitted; never fabricate
  around missing truth.
- No rows passing the disclosure policy → one bounded empty-state line.
- Missing snapshot, ready screen, finished screen, and the dedicated casevac presentation
  hide and re-stow the drawer.

   ANCA panel hides during casevac presentation; a MIST-style handoff checklist needs new
   sim state first.
- Player-performed checklists (rejected by doctrine).
- Post-sortie paperwork / logbook / claims (natural v2 on top of the engine).
- The medical Attention variant (future; module boundary drawn for it).
- anca2040.com landing page; DNS/Vercel domain wiring (owner action + one dashboard add).
