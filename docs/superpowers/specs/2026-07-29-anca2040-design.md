## One sentence

Guns Only stays Guns Only; it becomes the gateway title of the **ANCA2040** program
(Aviate, Navigate, Communicate, Administrate — a decision-sim curriculum aimed at the
2040 battlespace), and the program shows up in-game as a persistent, view-only **ANCA
situational-awareness panel** that displays what the jet's automation is doing for the
player on all four channels.

## Doctrine (binding constraints)

1. **AI-first redesign.** ANCA2040 trains for a battlespace where machines hold most of the
   shared mental model and speak most of the R/T. The panel and the radio are that redesign
   made playable: automation acts and narrates; the human judges. See
   `audio/radio/mission/README.md`.
2. **The automation does it; the panel shows it.** ANCA is an SA panel on what the jet
   is doing for the player automatically. No player chores, ever. Radio speaks sparse
   deltas; the panel holds continuous truth — never a task list.
3. **Presentation must not outrun the kernel.** Every rendered fact binds to sim truth
   already in (or added to) the snapshot. No client-side guessing.
4. **The HUD stays instrument-true.** The panel is a DOM element outside the HUD canvas,
   not a HUD symbol.
5. **Complexity ladder holds.** Portrait = max-simple gets the glanceable spine;
   laptop = max-complex gets the full panel.
6. **Teaching by exposure.** The panel is the radio doctrine's shared mental model made
   visible: who am I, where am I, what am I cleared for, what do I want. The player
   learns the ANCA scan by watching automation run it. Radio authoring follows the
   audience / delta / workload / ambient gate in `audio/radio/mission/README.md`.

## The ANCA panel — UX

Persistent at every tier, view-only.

**Portrait (max-simple):** four letter chips `[A][N][C][A]` stacked on the right edge,
positioned above stick clearance and outside the casevac facts reservation (exact anchors
resolved against existing layout constants and verified by screenshot). Each chip has a
state color: steady (dim), attention (amber), active (bright — e.g. a radio call in
progress). Tapping a chip slides out its one-line row for ~6 s.

**Laptop (max-complex):** the full four-row panel, top-right, outside the HUD zone.

| Row | Content (example) | Binds to |
|-----|-------------------|----------|
| **A** Aviate | `gear DN · flaps LDG · G-protect 7.3` | existing config/warning fields |
| **N** Navigate | `1 240 lb · JOKER −3 min · home CVA-31 42 nm` | `fuel_to_home_estimate_lb`, `fuel_minutes_to_joker/bingo`, `recovery_*` |
| **C** Communicate | `281.8 · next: base call`; live `radio_text` ticker while a call is active | `radio_*` block (MissionRadio's actual projected state) |
| **A** Administrate | `RECOVERY 1/2 · FLAPS LDG` | new `checklist_*` fields |

Row state → chip color mapping: attention when a threshold nears (joker/bingo, unsafe
config for phase, checklist item overdue relative to phase), active while its channel has
a live event (radio call, checklist item completing).

## Checklist engine (the one new sim subsystem)

`sim/MissionChecklists.cs` — checklist definitions as **data** per beat phase. V1
checklists, constrained to items with real sim truth behind them (implementation research
2026-07-29): **LAUNCH** (cat stroke, airborne, gear up, flaps up), **COMMIT** (the
fence-in substitute — Intercept-phase commit + weapons authorized; the sim has no
master-arm/fence switch), **RECOVERY** (gear down and locked, flaps landing — no hook
state exists [the hook is fixed geometry] and no harness state exists, so those items are
cut rather than faked). Design:

- Every item is a **predicate over sim truth** evaluated at tick boundaries. Items
  complete themselves because the automation genuinely did the thing. Nothing is ever
  handed to the player.
- Completion events are exposed to `MissionRadio` so admin milestones can be narrated
  in-register ("fence in" call) — the C and A channels tie together.
- State resets on beat start; each predicate fires exactly once per checklist activation.

**Snapshot additions:** a small `checklist_*` block — id/name, done count, total,
next-pending item label. Full contract ritual: `SnapshotHotFrame` LayoutVersion 16 → 17,
schema 1.21.0 → 1.22.0 in `SnapshotProjection.cs` **and both** `pack.json` copies, plus
every test pin (including the escaped-regex pins in
`g_tolerance_bridge_contract.test.mjs`).

## Modules and data flow

New `web/wwwroot/render/anca/`:

- `anca_view_model.js` — pure function: snapshot → four row structs
  (`{letter, state, line, detail}`). A/N/C compose here from existing fields; the fourth
  row binds `checklist_*`. Follows the `commander_view_model.js` pattern. Row definitions
  are data so the medical sim can later re-skin the first channel as Attention without
  touching the renderer.
- `anca_panel.js` — DOM renderer (spine + expandable rows), wired in `app.js`; styles
  follow existing panel CSS conventions.

## Error handling

- Missing / never-populated fields → the row renders a quiet "—"; never fabricates.
- No active checklist for the current phase → fourth chip dims.
- Stale snapshot → panel dims using the same staleness behavior the HUD uses.

## Testing

- `render/anca/tests/` view-model unit tests + app-wiring pin (auto-discovered by
  `bin/check`'s runtime-test sweep).
- C# tests for `MissionChecklists`: predicates fire exactly once, reset on beat start,
  ordering, radio-event handoff.
- Snapshot layout/schema contract pins updated with the bump.
- **Visual doctrine:** rendered screenshots of the panel — portrait spine, portrait
  expanded row, laptop full panel, attention/active states — via the scenario harness,
  eyeballed before shipping. Structural green is not sufficient for pixels.
- Build stamp ritual on the shipping commit (RELEASE_BUILD in all four places, stamp
  last).

## Explicitly out of scope

- Casevac/medevac rows in v1: casevac beats bypass the radio/checklist tick path and run
  their own dedicated presentation stack (which already surfaces handoff state), so the
  ANCA panel hides during casevac presentation; a MIST-style handoff checklist needs new
  sim state first. An RTB fuel checklist is also deferred — joker/bingo are already
  narrated by the radio and shown in the N row.
- Player-performed checklists (rejected by doctrine).
- Post-sortie paperwork / logbook / claims (natural v2 on top of the engine).
- The medical Attention variant (future; module boundary drawn for it).
- anca2040.com landing page; DNS/Vercel domain wiring (owner action + one dashboard add).
- Radio content expansion (already a recorded follow-up in
  `audio/radio/mission/README.md`).
